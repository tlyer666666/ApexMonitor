# MacPulse 系统性能监控器设计规格

> 日期：2026-09-28  
> 负责人：fengjinwen  
> 范围：macOS 原生菜单栏与实时系统性能总览

## 1. 背景与目标

MacPulse 面向个人日常使用，在 macOS 菜单栏持续显示一个紧凑的 CPU 使用率读数；用户点击图标后可以快速查看当前 CPU、内存、磁盘 I/O 与网络流量，并可打开更完整的可视化窗口。核心目标是让状态一眼可读、数据及时，同时将采样和界面自身开销控制在较低水平。

## 2. 产品范围

### 首版包含

- 原生 macOS 菜单栏常驻应用，不显示 Dock 图标。
- 菜单栏按钮显示 CPU 使用率，并处理采样尚未就绪、指标暂不可用的状态。
- 点击菜单栏按钮打开轻量状态弹层，展示 CPU（含最近 5 分钟迷你趋势）、内存使用量/比例、磁盘读写速率、网络上下行速率。
- 从弹层打开完整仪表盘：当前指标卡片 + 可切换时间范围（5分钟/15分钟/30分钟/1小时/24小时/7天）的趋势图与“平均/峰值”统计摘要。
- 约每秒采集一次；采样器独立于 UI 计算速率，所有展示消费同一份最新快照。
- 本机保留最近 7 天分钟级历史（均值/峰值，JSON 存储），不联网、不上传数据。
- 不需要管理员权限。

### 首版不包含

- 告警、进程级/应用级资源排行、导出。
- 登录账户、遥测、云端同步、自动更新、开机启动设置。
- 需要 root/helper/系统扩展的监控能力。

## 3. 关键交互

1. 应用启动后立即建立 CPU、磁盘和网络计数器基线，再进入稳定采样；尚无有效速率时显示“采集中”，不可用时显示“—”。
2. 菜单栏状态按钮展示 `CPU 12%` 形式的汇总 CPU 使用率，点击后切换弹层显示状态卡片。
3. 弹层按 CPU、内存、磁盘、网络顺序呈现；磁盘与网络分别显示读/写或收/发方向速率。
4. “打开监控面板”操作展示完整窗口。关闭窗口不终止菜单栏采集；从弹层点开窗口时收起弹层。
5. 仪表盘趋势只保存当前进程内最近 60 个有效采样点；退出应用后即丢弃。
6. 退出操作通过菜单栏弹层提供，停止采样并结束应用。

## 4. 架构与数据流

- 使用 Swift、SwiftUI、AppKit 与系统公开接口构建单进程原生菜单栏应用。
- `MetricsProvider` 从系统获取原始累计计数器/瞬时值；系统特定读取逻辑与纯计算逻辑分离。
- `MetricsCalculator` 使用相邻样本差和单调时间差计算 CPU 百分比及磁盘/网络字节每秒；累计计数器回退、首次基线、零/异常时间差都不能生成负速率或错误峰值。网络接口为 32 位计数，按接口展开回绕后再合计。
- `MetricsSampler` 在低优先级串行队列按约 1 秒节奏采集，设置合理 timer leeway，避免 UI 线程执行系统查询。采样失败时保留可用指标并将失败字段标成不可用。
- `MonitorStore` 持有最新不可变快照、逐秒样本（内存，约 2 小时）与分钟级历史桶（7 天，落盘 `~/Library/Application Support/MacPulse/history-v1.json`），并在主线程发布 UI 更新。状态栏弹层和仪表盘共享该 Store，不重复采集。
- `MetricsAggregator`/`HistoryAnalyzer`/`HistoryFileStore` 为纯核心逻辑：分钟桶聚合、跨重启重复桶合并、保留期剪枝、窗口序列与统计，全部有确定性测试。
- CPU 从主机处理器累计 tick 差计算，内存从物理内存总量、页大小与 VM page 计数计算，磁盘从 IOKit block storage 累计字节计数计算，网络从非 loopback 网卡字节计数计算。具体接口在实现时依据当前 SDK 可用公开 API 编译验证。

## 5. 界面与视觉方向

- 简洁、紧凑、原生 macOS 风格；信息层级优先突出当前数值和单位，颜色作为辅助而不单独承担含义。
- 菜单栏只占用短标签；弹层按指标分组，使用清晰图标/单位和适度留白；仪表盘在同一视觉体系下呈现更完整的指标卡片与趋势。
- 支持浅色/深色系统外观，避免依赖不可读的硬编码对比度。
- 使用系统字体、SF Symbols 与 SwiftUI 原生绘制，不引入第三方 UI 库或远程资源。

## 6. 非功能要求

- 采样目标约 1 Hz，全部系统采样与速率计算不在主线程运行。
- 采集和 UI 共享单份快照；不执行高频进程枚举或全盘扫描，不维持不必要的历史数组（最多 60 点）。
- 常规运行不请求管理员权限、不建立网络连接、不写入用户指标数据。
- CPU/磁盘/网络采样不可用时以占位状态呈现，应用继续显示其余成功指标。
- 采样任务在退出时可取消；计数器溢出、计数回退、首次采样或无效时间间隔均应安全处理。

## 7. 验收标准

- [ ] 使用提供的构建命令可生成 `MacPulse.app`，且 bundle 标识、菜单栏应用配置和最低系统版本均明确。
- [ ] 启动后出现菜单栏 CPU 读数；在可运行的 macOS 环境点击后弹层可打开并可再次关闭。
- [ ] 弹层与仪表盘展示 CPU、内存使用量/百分比、磁盘读/写速率、网络接收/发送速率，并标明单位。
- [ ] 仪表盘有最近 60 秒的内存趋势，样本数量有界且退出后不持久化。
- [ ] 首次样本、计数器重置、无效时间间隔和单个指标采集失败不会显示错误的负速率/伪零值。
- [ ] CPU、速率与格式化等纯逻辑有可重复的自动测试；完整构建通过。
- [ ] 文档说明运行/构建方式、权限与数据处理边界、已知的工具链限制。

## 8. 假设与开放限制

- 首版刷新周期采用约 1 秒；菜单栏展示 CPU 总使用率，其余指标在弹层和仪表盘中显示。
- 菜单栏趋势与其余历史均为运行时内存数据，不作持久化。
- 本机目前使用 Command Line Tools 而非完整 Xcode。将尝试使用安装的 macOS SDK 与 Swift 编译器构建、链接和启动；若当前 SDK/工具链缺少 SwiftUI 或 app 打包能力，需要在交付说明中区分验证通过项与受限项。
- 采集到的磁盘和网络速率是系统/设备总量近似值，可能包含后台服务或无法进一步归因的 I/O，不承诺进程级归属。
