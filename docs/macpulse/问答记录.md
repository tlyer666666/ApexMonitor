## 一、MacPulse 系统性能监控器

**Q1 这款监控工具主要供谁、在什么场景下使用？**  
A：个人日常监控，优先一眼看懂、轻量常驻，以菜单栏和简洁总览为主。

**Q2 主界面除了当前状态，还需要保留并展示近期趋势吗？**  
A：实时状态为主；不持久保存历史数据。实现约定：仪表盘仅展示最多 60 秒的内存迷你趋势，数据只存在进程内存。

**Q3 首版采用哪种技术路线？**  
A：原生 Swift（SwiftUI + AppKit），追求轻量运行与 macOS 系统集成。

**Q4 哪些性能指标必须展示？**  
A：CPU 使用率、内存占用、磁盘读写速度、网络流量；用户原始需求明确，无遗漏。

**Q5 用户如何打开与查看状态？**  
A：菜单栏小组件持续展示 CPU 概况，点击后快捷查看当前指标，并提供完整可视化界面。

**Q6 权限、遥测和启动行为有何要求？**  
A：用户要求低开销。实现约定：不请求管理员权限、不联网/遥测、不默认开机启动；不支持的系统指标显示“—”，首次采样速率显示“采集中”。

## 二、UI 与交互约定

- 信息顺序：CPU、内存、磁盘、网络；磁盘区分读/写，网络区分收/发。
- 菜单栏占用保持短小，显示 CPU 汇总百分比。
- 弹层提供当前指标快览、打开监控面板和退出入口。
- 仪表盘使用原生简洁卡片与历史趋势；支持系统浅色/深色外观。
- 无 PRD 截图或原型；具体间距、色彩和排版采用原生 macOS 视觉语言由实现方确定。

## 三、MPC002 分类详情面板（v1.2，2026-09-28）

**Q1 详情面板覆盖哪些分类？**
A：需求为"内存、磁盘、网络等"，按完整四类实现：CPU、内存、磁盘、网络，主界面四张卡片均可点击进入。

**Q2 "内存可用容量"口径？**
A：物理内存总量 − 已用（已用 = active + wired + 压缩器页，与总览一致），避免同一界面两种口径。

**Q3 "进程占用"展示什么、性能如何控制？**
A：按内存占用 Top 进程（CPU 详情页含按 CPU 占用 Top）；仅在对应详情页打开时以约 2 秒节流采样（libproc 同用户进程，无需新权限），关闭即停，保持常驻低开销。

**Q4 "连接状态"口径？**
A：在线状态用 Network.framework 路径监视（事件驱动、无轮询）；每接口明细（UP/RUNNING、IPv4/IPv6 地址、运行期收发累计）用 getifaddrs，同秒级采样复用。

**Q5 "磁盘剩余空间"范围？**
A：根卷为主，同时列出已挂载卷的容量/可用空间（FileManager 公开 API，详情页打开时读取）。

**缺口：无 PRD 截图/原型**
A：视觉按既有原生 macOS 风格与中文文案习惯实现；字段顺序按"总览数值 → 细分明细 → 列表"层级排布。
