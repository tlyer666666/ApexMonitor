# MacPulse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a lightweight native macOS menu bar app that shows live CPU, memory, disk, and network metrics in a popover and dashboard.

**Architecture:** A Swift Package separates deterministic metric models/calculations from the macOS app. One low-priority sampler reads system counters, creates one snapshot per interval, and publishes it to a shared main-thread store used by both SwiftUI views; an AppKit status item hosts the popover and dashboard window. A packaging script places the built executable and Info.plist into `dist/MacPulse.app`.

**Tech Stack:** Swift 6 compiler in Swift 5 language mode, Swift Package Manager, Foundation, AppKit, SwiftUI, Darwin/Mach, IOKit, XCTest.

**Spec:** `docs/superpowers/specs/2026-09-28-macpulse-design.md`

## Global Constraints

- Refresh metrics approximately every 1 second on a utility queue.
- Do not request administrator privileges, open network connections, upload telemetry, or persist performance history.
- Keep no more than 60 in-memory trend samples.
- Use one shared latest metrics snapshot for both the menu popover and dashboard.
- Show an unavailable marker instead of fabricating zero values when a counter is missing or invalid.
- Keep the application accessory-only (no Dock icon); do not add login items, alerts, process rankings, or third-party runtime dependencies.
- Build for macOS 13 or newer unless the installed SDK forces a different verified minimum.

## Review Focus

- A first sample, missing baseline, or counter reset must not create negative or false-zero rates; exercise this in `MetricsCalculatorTests`.
- Zero, negative, or non-finite elapsed time must not create an infinite/negative rate; exercise this in `MetricsCalculatorTests`.
- A missing individual system counter must leave other valid metrics visible; exercise optional raw sample fields and provider smoke checks.
- A host without a usable IOKit storage counter or network interface must show `—`, not crash; manually validate reader failure paths and provider output.
- A flat or one-point history must draw a bounded trend without division by zero; exercise the `MemoryTrendShape` edge case in the app test/build review and validate it in the dashboard.

## Task 2: System Counter Reader and Sampler

**Files:**
- Create: `Sources/MacPulseApp/Monitoring/SystemMetricsReader.swift`
- Create: `Sources/MacPulseApp/Monitoring/MetricsSampler.swift`
- Create: `Sources/MacPulseApp/Monitoring/MonitorStore.swift`
- Modify: `Package.swift` only if the local SDK requires an explicit framework linkage setting.

**Interfaces:**
- `SystemMetricsReader.read() -> RawMetricsSample` reads each counter independently; unsupported data remains nil.
- `MetricsSampler.start(deliver:)` emits one `MetricsSnapshot` per approximately one-second interval on a utility queue; `stop()` cancels the timer.
- `MonitorStore` publishes `snapshot` and `memoryHistory`; `memoryHistory` contains at most 60 valid memory-percentage samples.

- [ ] **Step 1: Compile-probe the local SDK for SwiftUI, AppKit, IOKit, and Mach imports**

Run: `swift -e 'import SwiftUI; import AppKit; import IOKit; import Darwin; print("macOS frameworks available")'`  
Expected: prints `macOS frameworks available`; if not, record the exact missing module and use the installed SDK-supported fallback without silently claiming a full app build.

- [ ] **Step 2: Implement counter reads independently**

Use `host_processor_info` with explicit `vm_deallocate` cleanup for CPU ticks; `host_statistics64` plus `ProcessInfo.processInfo.physicalMemory` for active+wired+compressed memory; IOKit block-storage `Statistics` for read/write byte totals; and `getifaddrs` AF_LINK `if_data` totals while excluding loopback for network bytes. Always release IOKit iterators/objects and `freeifaddrs` buffers; return nil for only the metric whose read failed.

- [ ] **Step 3: Add the cancellable low-priority sampler and shared store**

Schedule `DispatchSourceTimer` at one-second intervals with leeway on a `.utility` queue. Update the calculator on that queue and deliver immutable snapshots to `MonitorStore` on the main actor. Store at most the most recent 60 valid memory values and stop the timer when the app terminates.

- [ ] **Step 4: Compile the app target and run core tests**

Run: `swift test`  
Expected: native framework imports and system counter calls compile, and the deterministic core tests remain green.
